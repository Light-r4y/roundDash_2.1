# Ручное тестирование веб-интерфейса (без прошивки/железа)

Мок-сервер для проверки страниц из `fw/www` в обычном браузере на компьютере,
без ESP32 и без сборки прошивки.

## Запуск

```
python tools/webtest/mock_server.py
```

(или `python3`; по умолчанию порт 8088, другой порт — первым аргументом:
`python mock_server.py 8090`; `--password ПАРОЛЬ` включает защиту паролем)

Затем открыть в браузере:

- `http://localhost:8088/` — главная: состояние, яркость
- `http://localhost:8088/editor.html` — редактор экранов
- `http://localhost:8088/media.html` — картинки и шрифты
- `http://localhost:8088/can.html` — настройки CAN, привязки, сниффер
- `http://localhost:8088/imu.html` — датчик: калибровка, направление «вперёд», живая точка
- `http://localhost:8088/access.html` — пароль на настройки и Wi-Fi точки доступа
- `http://localhost:8088/sound.html` — звук: режим, правила тревог, пробный писк
- `http://localhost:8088/ota` — обновление прошивки и веб-интерфейса

## Что это делает

- Раздаёт статику напрямую из `fw/www` — тот же набор файлов, что попадёт в
  образ раздела www. Правки видны сразу после обновления страницы.
- Отдаёт `/ota` прямо из `fw/tasks/webcfg/ota_page.h` — проверяется настоящая
  страница из прошивки.
- Берёт встроенную раскладку из `fw/common/config/layout_default.h` — ту же, что
  компилируется в прошивку.
- Подменяет `/api/*` эндпоинты из `docs/fw-design.md` §8:
  - `/api/status`, `/api/auth/status`, `/api/auth/verify`, `/api/auth/password`;
  - `/api/display` (яркость);
  - `/api/wifi` — имя и пароль сети; как на плате, меняются только при заданном пароле на настройки;
  - `/api/layout`, `/api/layout/reset` — раскладка проверяется так же, как в прошивке
    (JSON, хотя бы один годный экран, до 16 КБ, не больше 4 разных фонов);
  - `/api/media`, `/api/media/delete`, `/media/<файл>` — файлы хранятся в памяти;
  - `/api/can`, `/api/can/map` (по умолчанию пресет rusEFI из `can_map_default.h`), `/api/can/map/reset`,
    `/api/can/frames` — настройки и привязки хранятся в
    памяти, `frames` отдаёт поддельные кадры с меняющимися данными (ID `0x201`,
    `0x3B3`, `0x420`, `0x7E8` и один 29-битный). Как и плата, первый запрос после
    паузы возвращает пустой список: приём чужих ID включается самим запросом;
  - `/api/sound`, `/api/sound/rules` (по умолчанию правила из `alerts_default.h`), `/api/sound/rules/reset`,
    `/api/sound/test` — режим и правила хранятся в памяти, тревога по первому правилу имитируется (5 с из каждых 10);
  - `/api/imu`, `/api/imu/calibrate`, `/api/imu/forward` — плавное движение точки; калибровка и определение
    «вперёд» занимают 1–3 с, как на плате, каждый вариант «вперёд» поворачивает оси на 90 градусов;
  - `/api/ota/update`, `/api/www/update` — загрузка только имитируется.

## Ограничения

- Состояние хранится только в памяти процесса — перезапуск сервера сбрасывает
  его (раскладка, таблица CAN, картинки, пароль, яркость).
- Загрузка образов на `/ota` только имитируется, ничего не записывается.
  Сценарии сбоев включаются параметром в адресе эндпоинта: `?fail=1` — ошибка
  записи, `?hang=1` — оборванное соединение, `?stall=1` — ответ не приходит,
  `?same=1` — загружен тот же образ.
- Мок не рисует экран и не гоняет сигналы: живой вид — только предпросмотр в
  редакторе. Проверка записей CAN-таблицы упрощена по сравнению с `can_map.c`
  (клиентские правила страницы `can.html` строже и совпадают с прошивкой).
- В панели браузера, встроенной в среду разработки, Alpine может не обновлять
  `x-show`, пока страница не отрисована (он применяется через
  `requestAnimationFrame`); в обычном браузере этого нет.
