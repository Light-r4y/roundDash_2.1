# roundGauge — прошивка

Приборка на Waveshare ESP32-S3-Touch-LCD-2.1: данные по CAN, настройка по Wi-Fi,
две кнопки на разъёме платы. ESP-IDF v6.0, цель `esp32s3`, LVGL 9.

Сейчас это **каркас**: экран и тач работают (тестовая шкала), остальные задачи —
пустые циклы с `TODO`. Ниже описаны принятые решения и то, что ещё не решено.

## 1. Структура проекта

```
fw/
├── CMakeLists.txt          EXTRA_COMPONENT_DIRS = tasks, common; образы www и media
├── sdkconfig.defaults
├── partitions.csv
├── version.txt             версия приложения, пишет tools/build/build.*
├── main/
│   └── main.c              инициализация, запуск задач, больше ничего
├── tasks/                  каждая FreeRTOS-задача — отдельный компонент
│   ├── can/                can_task: приём TWAI, разбор сигналов
│   ├── ui/                 ui_task: LVGL через esp_lvgl_port, экраны (пока тестовый)
│   ├── buttons/            buttons_task: опрос двух кнопок
│   └── webcfg/             webcfg_task: точка доступа, HTTP, OTA-страница
├── common/
│   ├── board/              карта пинов, I2C, TCA9554, экран ST7701, тач, подсветка
│   └── config/             conf.h, настройки в NVS (JSON), пароль веба
├── www/                    → раздел www   (веб-интерфейс)
└── media/                  → раздел media (картинки приборки)
```

Соглашения (как в wifi-serv):

- файлы задачи `<x>_task.c/.h` лежат рядом, запуск — `roundGauge_<x>_task_start()`;
- функции и типы — префикс `roundGauge_`, макросы — `RG_`;
- стек, приоритет и ядро всех задач — в `common/config/conf.h`;
- **номера GPIO встречаются только в `common/board/board.h`.**

Файлы `sdkconfig`, `build/`, `managed_components/` и `dependencies.lock`
генерируются и в репозиторий не идут.

## 2. Задачи

| Задача | Ядро | Приоритет | Стек | Период | Роль |
|---|---|---|---|---|---|
| esp_lvgl_port | 1 | 4 | 8 K | — | `lv_timer_handler`, рендер |
| `ui_task` | 1 | 3 | 4 K | 33 мс | значения сигналов → виджеты под `lvgl_port_lock()`, экраны |
| `can_task` | 0 | 8 | 4 K | по кадру | разбор кадров из очереди |
| `buttons_task` | 0 | 5 | 2.5 K | 10 мс | опрос кнопок, долгое нажатие → AP |
| `webcfg_task` | 0 | 2 | 4 K | 500 мс | подъём точки доступа по запросу |
| httpd | 0 | 5 | 8 K | по запросу | создаёт esp_http_server |

Ядро 1 целиком под отрисовку. Wi-Fi работает на ядре 0, но включается только в
режиме настройки, поэтому в обычной езде CAN и кнопки ядро ни с кем не делят.

`CONFIG_FREERTOS_HZ=1000`: ровные периоды 10 и 33 мс.

Путь кадра CAN:

```
TWAI ISR (on_rx_done) ──xQueueSendFromISR──> q_rx(RG_CAN_RX_QUEUE_LEN) ──> can_task
                                                                            ├─> значения сигналов ──> ui_task
                                                                            └─> сниффер ──> веб
```

ISR только кладёт кадр в очередь: поиск по таблице сигналов и арифметика в
прерывании не нужны.

## 3. Железо и распиновка

Все внешние сигналы — на разъёме J9 «12PIN Multi-function Interface»:

| Пин J9 | Сигнал | Назначение |
|---|---|---|
| 2 | 5V | питание от DC-DC 12→5 В |
| 1, 5, 11 | GND | |
| 6 | 3V3 | питание трансивера |
| 3 | GPIO19 | CAN RX |
| 4 | GPIO20 | CAN TX |
| 12 | GPIO0 | кнопка 1 (параллельно BOOT) |
| 10 | GPIO44 | кнопка 2 |
| 9 | GPIO43 | логи (UART0 TX) |
| 7, 8 | GPIO7/15 | I2C платы, резерв |

- **CAN** — внешний трансивер 3.3 В (SN65HVD230 или TJA1051T/3). При подключении
  к штатной шине терминатор 120 Ом на модуле трансивера снять.
- **Питать через пин 2 J9, не через Type-C.** Переключатель FSUSB42 отдаёт
  GPIO43/44 микросхеме CH343, пока на Type-C есть VBUS, и кнопка 2 в это время
  отключена от разъёма.
- **Кнопка 1 на GPIO0** — strapping-пин: зажатая при включении, переводит плату
  в режим прошивки.
- **USB-Serial/JTAG выключен** (`CONFIG_ESP_CONSOLE_SECONDARY_NONE`) — его пины
  отданы CAN. Консоль только на вывод: RX UART0 занят кнопкой 2.
- Кнопки замыкают на GND; на линии GPIO44 нужны внешние 10 кОм к 3V3 и 100 нФ
  на GND (у GPIO0 подтяжка уже есть на плате).

Полная карта пинов платы (экран, тач, TCA9554, I2C-адреса) — в
`common/board/board.h`. Схема и даташиты микросхем платы — в `hw/`
([hw/README.md](../hw/README.md)).

### 3.1. Экран и тач

Init-последовательность ST7701S, тайминги и порядок сбросов взяты из
конфигурации этой платы от Waveshare в библиотеке
[ESP32_Display_Panel](https://github.com/esp-arduino-libs/ESP32_Display_Panel/blob/master/src/board/supported/waveshare/BOARD_WAVESHARE_ESP32_S3_TOUCH_LCD_2_1.h)
(Apache-2.0, перенесено в `common/board/st7701_init.h` с указанием источника).

| Параметр | Значение |
|---|---|
| PCLK | 16 МГц |
| HSYNC: pulse / back / front | 8 / 10 / 50 |
| VSYNC: pulse / back / front | 3 / 8 / 8 |
| Шина | RGB565, 16 линий |
| Кадровые буферы | 2 × 450 КБ в PSRAM |
| Bounce-буфер | 480 × 10 пикселей во внутренней RAM |

Порядок в `roundGauge_board_init()`:

1. подсветка (LEDC на GPIO6, 5 кГц) — сразу в 0, чтобы не мелькал мусор;
2. I2C 400 кГц на GPIO7/15, TCA9554 (0x20): выходами — только LCD_RST, TP_RST, LCD_CS;
3. сброс экрана через TCA9554 (10 мс низкий, 100 мс высокий), 3-wire SPI
   (SCL/SDA на GPIO2/1, CS на TCA9554), `esp_lcd_new_panel_st7701()` → reset → init;
4. сброс тача (30 / 50 мс), CST820 через драйвер CST816S, прерывание на GPIO16.

`ui_task` поднимает LVGL через esp_lvgl_port в режиме **без разрывов**: LVGL
рисует прямо в кадровые буферы панели (direct mode), буферы меняются по
окончании кадра. Тач работает по прерыванию: CST820 засыпает без касания и не
отвечает по I2C, а esp_lvgl_port в режиме событий читает его только после
прерывания. Подсветка включается через 100 мс после первого кадра,
яркость — `RG_LCD_BL_DEFAULT_PCT` (100 %).

Настройки под RGB-экран в `sdkconfig.defaults` (рекомендации Espressif для
ESP32-S3): CPU 240 МГц, PSRAM 80 МГц, исполнение кода из PSRAM
(`SPIRAM_XIP_FROM_PSRAM` — запись во флеш не останавливает вывод кадра), строка
кэша данных 64 байта, прерывания RGB в IRAM, перезапуск DMA на каждом VSYNC,
оптимизация `-O2`.

Тестовый экран (`tasks/ui/test_screen.c`): шкала на 270°, стрелку гоняет
анимация 0→100→0 за 4 с — видно плавность и разрывы; в центре `roundGauge`,
значение и версия прошивки; под пальцем — точка.

## 5. Хранение

| Что | Где | Как |
|---|---|---|
| Веб-интерфейс | раздел `www`, `/www` | образ из `fw/www/`, обновляется целиком (`/ota`) |
| Фоны, стрелки, картинки | раздел `media`, `/media` | базовый набор из `fw/media/` + загрузка через веб по файлу |
| Общие настройки, CAN | NVS `rg_cfg` / `cfg` | JSON-blob |
| Пароль веба | NVS `rg_cfg` / `auth_hash` | SHA-256(соль + пароль) |

Оба образа SPIFFS собираются с `FLASH_IN_PROJECT`: **`idf.py flash` возвращает
media к базовому набору и стирает загруженные через веб файлы.** Так решено
осознанно — для разработки удобнее.

Настройки в JSON: добавление полей их не сбрасывает, отсутствующие поля берутся из
значений по умолчанию. Применяются перезагрузкой.

```json
{
  "version": 1,
  "can":     { "bitrate": 500000, "mode": "listen_only" },
  "wifi_ap": { "ssid": "", "password": "roundgauge" }
}
```

| Поле | Значения | По умолчанию |
|---|---|---|
| `can.bitrate` | бит/с | 500000 |
| `can.mode` | `listen_only` \| `normal` | `listen_only` — новая приборка ничего не передаёт в шину |
| `wifi_ap.ssid` | строка, пусто = `roundGauge-XXXX` по MAC | пусто |
| `wifi_ap.password` | 8–64 символа, WPA2 | `roundgauge` |

`normal` нужен для запросов OBD-PID: в режиме прослушивания контроллер не
ставит даже ACK.

## 6. Wi-Fi и веб

- Точка доступа выключена. **Долгое нажатие кнопки 1 (2 с)** её поднимает,
  гаснет она только с перезагрузкой.
- Веб-стек перенесён из wifi-serv: Alpine.js, Bootstrap, FontAwesome (только
  solid, только woff2), светлая/тёмная тема, RU/EN, необязательный пароль на
  изменяющие запросы и OTA.
- Страница `/ota` вшита в прошивку (`tasks/webcfg/ota_page.h`), а не лежит в
  www: она должна работать и тогда, когда раздел www пуст или перезаписывается.

Эндпоинты, которые уже ждёт `/ota` (взяты по аналогии с wifi-serv):

| Метод | Путь | Смысл |
|---|---|---|
| `POST` | `/api/ota/update` | прошивка |
| `POST` | `/api/www/update` | образ раздела www целиком |
| `GET` | `/api/status` | состояние; итог обновления www в поле `www_update` |
| `GET` | `/api/auth/status` | включён ли пароль |
| `POST` | `/api/auth/verify` | проверка пароля (Basic) |

## 8. Сборка, версии, релизы

- **Версия** — `0.<ГГ>.<ММДД>`; её пишет в `fw/version.txt` релизный скрипт, а
  ESP-IDF берёт оттуда версию приложения (она же на тестовом экране).
- **Уровень логов**: обычный `idf.py build` — INFO; релизная сборка передаёт
  `-D RG_LOG_LEVEL=WARN` (`fw/CMakeLists.txt` → `RG_LOG_LEVEL_STR` → `main.c`) и
  сразу возвращает кэш CMake к INFO.
- **`tools/build/build.bat` / `build.sh`** — как в wifi-serv: сами активируют
  ESP-IDF, генерируют `fw/www/.build_id`, собирают и складывают в
  `releases/roundGauge_v<версия>_<время>/` полный комплект для прошивки по USB:
  `roundGauge_firmware_v*.bin`, `roundGauge_www_v*.bin`, `roundGauge_media_v*.bin`,
  `bootloader.bin`, `partition-table.bin`, `ota_data_initial.bin`, `flash_args`
  (смещения из сборки, имена файлов релиза) и `README.txt`. Папка `releases/` в
  git не идёт.
- **`tools/webtest/mock_server.py`** — раздаёт `fw/www` и `/ota` из
  `ota_page.h`, имитирует эндпоинты §6.
- `.gitattributes` фиксирует CRLF для `*.bat` и LF для `*.sh`: иначе `cmd.exe`
  или bash не разберут скрипт.
